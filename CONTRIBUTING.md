# Contributing to The Nexment Project

Thank you for your interest in contributing to Nexment.

Nexment is built in the open, and many of our repositories welcome contributions. However, **not every Nexment repository is open for contributions**.

Before making changes, always read the `CONTRIBUTING.md` file in the specific repository you want to contribute to.

The repository's own contribution guidelines take priority over this general document.

## Before You Contribute

Please check the repository first.

A repository may not accept contributions because it is:

- Still under active development.
- Based on incomplete or experimental code.
- Not yet stable.
- Before its first stable/V1 release.
- A private implementation or internal project.
- Explicitly marked as not accepting contributions.

If a repository says that contributions are not currently accepted, please respect that decision.

Do not open pull requests simply because the repository is publicly visible.

## Websites

The source code for Nexment websites is **not open for external contributions**.

This includes, but is not limited to:

- Nexment main website.
- Nexment Academy.
- Nexment Dev Community.
- Other official Nexment web platforms and services.

You may still report bugs, security issues, accessibility problems, or other useful feedback through the appropriate channels.

## How to Contribute

For repositories that accept contributions:

1. Read the repository's `README.md`.
2. Read its `CONTRIBUTING.md`.
3. Check existing issues and discussions.
4. Look for contribution guidelines or open tasks.
5. Fork the repository if required.
6. Create a focused branch for your changes.
7. Make your changes.
8. Test your changes properly.
9. Submit a pull request with a clear description.

Keep pull requests focused. Avoid mixing unrelated changes into the same contribution.

## Code Quality

Contributions should:

- Follow the project's existing structure and conventions.
- Be understandable and maintainable.
- Include appropriate tests where applicable.
- Avoid unnecessary dependencies.
- Avoid unrelated refactoring.
- Include documentation when the change requires it.

Do not submit generated or AI-generated code without understanding and reviewing it yourself.

You are responsible for the code you contribute.

## Issues and Discussions

Before opening an issue, check whether a similar issue already exists.

When reporting a problem, provide enough information for someone else to reproduce and understand it.

For feature requests, explain the problem the feature would solve rather than only describing the feature itself.

Be respectful when discussing disagreements.

## Pull Requests

A pull request may be reviewed, requested for changes, accepted, or rejected.

Opening a pull request does not guarantee that it will be merged.

Maintainers may reject contributions that do not fit the project's direction, architecture, scope, quality standards, or current development stage.

Please do not take rejection personally.

## Security

Do not publicly disclose security vulnerabilities.

Follow the security reporting instructions provided by Nexment or the individual repository.

## Code of Conduct

All contributions and interactions are subject to the [Nexment Code of Conduct](./CODE_OF_CONDUCT.md).

By contributing to Nexment, you agree to follow those standards.

## Final Note

Nexment is built by people who care about making useful things.

We appreciate thoughtful contributions, useful feedback, bug reports, documentation improvements, and ideas.

Not every repository is ready for contributions, and that's okay.

**Read the repository. Understand the project. Then contribute where contributions are welcome.**
